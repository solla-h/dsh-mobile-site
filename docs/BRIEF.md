# 网站内容与设计交接

> 初始设计交接于 2026-11-06；中文与英文页面已完成，正在接通首次发布。
> 实际上线状态与部署参数见 [DEPLOYMENT.md](DEPLOYMENT.md)。

## 目标

两个入口解决不同问题：

| 入口 | 读者的问题 | 主要行动 |
| --- | --- | --- |
| GitHub README（App 仓库） | 这是什么，能否试用，怎么安装或参与？ | 下载 APK、读安装指南、反馈/贡献 |
| 本宣传站 | 我为什么要在手机上使用 DSH？ | 理解场景 → 确认前提 → 下载与配对 |

网站提供简体中文和英文；App 界面仍是简体中文，App i18n 暂缓。网站不重复整套手册，不承担登录、配对、网关代理或对话服务。
不虚构用户数量、评价、性能指标或未经验证的能力；没有注册墙、留言表单、统计 SDK
或营销追踪，反馈统一走 GitHub Issues。

## 内容槽位（顺序可微调，事实边界不可破）

| 顺序 | 模块 | 必须回答 | 交互 |
| --- | --- | --- | --- |
| 1 | 简洁导航 | 产品名、能力介绍、开始使用、GitHub | 锚点导航，手机上一眼可读 |
| 2 | 首屏 | 给谁用、带来什么价值；第三方 DSH 手机客户端、Android alpha | 主按钮：获取 Android APK；次入口：安装与配对 |
| 3 | 核心场景 | 看进度：运行/待办；做决定：回复审批/提问；继续说：文字/语音 | 三个短场景，写用户动作和收益，不堆协议名 |
| 4 | 产品展示 | 从首页进入会话、处理待办、继续对话 | 1–2 张脱敏真机图优先；没有时用明确标注的界面示意 |
| 5 | 三步开始 | 已有 DSH 宿主 → 安装手机网关并生成配对码 → 安装 APK 后扫码 | 说明宿主持续运行、手机能访问网关；链接中文指南与 Agent 手册 |
| 6 | 使用边界与 FAQ | 是否官方、需要什么、语音条件、断线行为、iOS、数据与许可 | 原生可展开问答；关键前提在首屏附近也提示 |
| 7 | 收尾与页脚 | 下载、阅读文档、反馈问题、查看源码 | alpha 状态、独立项目声明、代码与素材许可 |

**桌面：** 首屏左侧价值与行动，右侧产品图；中段三种场景，随后上手步骤与 FAQ。
**手机：** 单列；先身份、前提和行动，再产品图；导航与长标题不能挤出屏幕。
不做全屏自动播放、强制弹窗或遮挡内容的悬浮层；末尾再放一次下载入口。

## 事实边界

| 可以表达 | 必须同时说明 |
| --- | --- |
| 在手机上查看 DSH 会话、进度和待办，处理审批与提问 | DSH 运行在用户自己的宿主上；这不是手机本地模型或托管 AI 服务 |
| 按住说话、转写后继续对话 | 宿主需要匹配的语音插件及就绪的识别模型 |
| 离线保留列表、草稿，文字进入发件箱 | 发送和执行仍需恢复连接；附件上传需要在线 |
| 多网关切换、扫码配对 | 每个网关分别配对，手机需能访问对应入口 |
| 可选加密地址簿帮助找回变化的入口 | 只加密入口地址，不等于所有会话端到端加密；也不是使用前提 |
| Android APK 可下载 | 当前为 alpha、侧载安装；不宣称应用商店发行或稳定版 |
| 开源 | 原创代码 MIT；宠物素材 CC BY-NC-SA 4.0，仅限非商业；不要统称全部素材 MIT |

不要宣称：系统推送通知、后台始终在线、永不断线、零数据留存、所有 Android 机型兼容、
iOS 已可用。页面不放真实主机地址、配对码、设备标识、账号或用户对话。
宣传站不使用真实网关作为交互演示后端。

## 验收旅程

手机打开首页 → 看懂产品及使用前提 → 看一段场景/展示 → 打开 Releases 找到 APK →
返回页面打开安装指南 → 展开 FAQ → 找到反馈入口。桌面同样走一遍。
检查 360px 窄屏无横向滚动、200% 缩放、键盘焦点、链接名称/对比度、图片替代文本，
以及加载失败时的可读性。

DSH Mobile App 版本兼容说明

DSH Mobile App 说的是 dsh-mobile-v1 协议，但协议号、手机网关插件和 DSH 宿主各自独立发版：协议号相同，不代表新的 DSH、Node 或插件版本就被支持。本站只做介绍，不替代 App 仓库的锁定文件；本页数值核对于 2026-11-11，实际安装前请以 compatibility.json 与 COMPATIBILITY.md 的当前内容为准。

匹配策略

不匹配时，停下来

锁定文件把策略写成了机器可读字段，不是一句「建议」。

策略实际含义

  • requireExactMatch: true

    前提只使用 recommended 中的精确版本。共享同一协议号并不构成支持新 DSH、Node 或插件版本的证据。

  • onMismatch: stop-and-ask

    前提宿主上的 DSH 或插件版本不一致时，停下来核对并询问，不要自动升级任意一侧，也不要「先装着试试」。

  • allowLocalCheckout: false

    前提不要用本地 git clone、link: 依赖或 profile 备份安装网关；上游插件与本项目维护的 fork 不能同时安装，也不能因为版本字符串相同就替换来源。

  • 语音单独核对

    前提语音包是宿主侧可选附加项，与 DSH 版本精确对应，模型也需就绪；它不随网关协议条目一起被「带过来」。

未覆盖

iOS；0.2.1-rc.5 以外的 DSH 版本；上述已验证与推荐条目以外的网关版本；从本地 clone 或 link: 依赖安装。文档里的「未覆盖」意思是停下来询问，不是试一试；也不代表所有 Android 机型都已验证。

常见疑问

关于版本，最常问的三件事

可以用 @latest 装网关吗？

不可以。网关来源是带精确 GitHub 标签的 fork，不是 npm 版本线；使用 @latest、本地 checkout 或同名上游包都会脱离已验证组合。安装脚本会读取锁定文件并校验已安装包的来源与版本。

协议号一样，为什么还要锁 DSH 和插件版本？

网关的 hello 只公布协议号与构建时的 DSH 版本，不公布插件版本；协议号相同不代表新版本的上游依赖、行为或宿主能力已被验证。兼容说明把这一点列为前提，而不是可选项。

升级 APK 会不会改变兼容组合？

以新版本 App 仓库当前的 compatibility.json 为准重新核对，不要把旧页面的数值沿用过去。升级 APK 时直接覆盖安装、不要先卸载；若宿主侧组合已不在锁定范围，先停下来确认再继续。完整安装顺序见安装与配对教程。
